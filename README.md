# 출석 - 구현 기능 정리

## View
### InputView
- 기능 구현
    - [x] 1. 출석 확인
      - [x] 닉네임 입력
      - [x] 등교 시간 입력
    - [x] 2. 출석 수정
      - [x] 닉네임 입력
      - [x] 수정하려는 날짜 입력
      - [x] 수정 시간 입력
    - [x] 3. 크루 출석 기록 확인
      - [x] 닉네임 입력
    - [ ] 4. 제적 위험자 확인
- 예외 처리
    - [x] 입력 시간이 00:00을 넘어갈 경우 (00:00 ~ 23:59 까지의 범위만 가능하다.)
    - [ ] 등록되지 않은 닉네임일 경우
    - [x] 공휴일 (토, 일요일) 인데 1번을 클릭할 경우
    - [x] 08:00 ~ 23:00 사이에만 출석이 가능하다.

### OutputView
- 기능 구현
    - [x] 1. 출석 확인
        - [x] 출석 확인 후 오늘 출석 현황 출력
    - [x] 2. 출석 수정
        - [x] 출석 수정 후 해당 날짜 변경 사항 출력 (미리 변경 전 데이터를 저장해서 넘겨주는게 좋을듯)
    - [x] 3. 크루 출석 기록 확인
        - [x] 해당 크루 출석 기록
        - [x] 해당 크루의 출석, 지각, 결석 횟수
        - [x] 제적, 면담 대상자 여부
    - [ ] 4. 제적 위험자 확인
        - [ ] 제적 대상자 여부 출력
        - [ ] 제적 대상자들은 제적 - 면담 - 경고 순으로 출력

    - [x] 제적 상태를 update 할 수 있는 로직이 존재한다.

- 예외 처리
    - [ ] 

### Attendance
- 기능 구현
    - [x] 출석 가능 시작 시간, 종료 시간, 출석 날짜, 출석 시간, 해당 출석 상태 (지각, 결석, 양호)가 존재한다.
    - [x] 출석 상태를 update 할 수 있는 로직이 있다.
      - [x] 출석 수정시, 반드시 같이 업데이트 해야 한다.
    - [x] getter
- 예외 처리
    - [x] 출석 시간이 시작 시간과 종료 시간 사이가 아니면 예외 처리
    - [x] 출석 시도 날짜가 토, 일요일이면 예외 처리

### Status (ENUM)
- 기능 구현
    - [x] 유저의 현재 상태를 나타낸다.
    - [x] 양호, 제적, 면담, 위험으로 나뉜다.
    - [x] 양호의 경우는 결석 2회 미만이다.
    - [x] 경고의 경우는 결석 3회 미만이다.
    - [x] 면담의 경우는 결석 6회 미만이다.
    - [x] 제적의 경우는 결석 6회 이상이다.
    - [x] 결석 횟수를 보고 상태를 출력하는 로직이 필요하다.
- 예외 처리
    - [ ]

### Rate (ENUM)
- 기능 구현
    - [x] 해당 날짜의 상태를 나타내기 위함이다.
    - [x] 세이프, 지각, 결석으로 나뉜다.
    - [x] 세이프의 경우는 시작 시간 5분 미만 까지이다. 
    - [x] 지각의 경우는 시작 시간 30분 미만 까지이다.
    - [x] 결석의 경우는 30분 이상이거나 안 온 경우이다.
    - [x] 이름, 몇 분 미만인지, 월요일 시작 시간, 화~금요일 시작 시간 이렇게 필드를 가진다.
- 예외 처리
    - [ ]
